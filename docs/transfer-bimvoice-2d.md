# Transfer from BIMvoice CDE: 2D drawings and sheets

What the user wrote for 2D plans and sheets in the BIMvoice CDE (`~/Documents/GitHub/bimvoice-cde`, AGPL-3.0, his own
repository), compared with what Lapin's main has on 23.11.2026, and what is worth bringing over. Analysis only: no code
moved yet.

Read on the BIMvoice side: `docs/planse-din-model.md`, `docs/ifc.md`, `docs/coordonare.md`, `docs/issues.md`,
`README.md`, `apps/web/src/components/{Views2D.tsx, auto-annotations.ts, anno-dxf.ts, drawing-frame.ts, SheetDialog.tsx,
SheetsPanel.tsx, markup.tsx}`, `core/src/modules/{sheets.ts, ifcdocs.ts}`, `core/src/vendor/ifcsheet/`.

## Licence: what may be used, and how

BIMvoice's 2D work sits on three layers, and only one of them is the user's alone.

| Layer | Files | Licence and authorship | Use in Lapin |
|---|---|---|---|

Clean references: `readGrids` / `readTrueNorth` / `stepClosure` in `ifcdocs.ts` (the user's own STEP streaming), `nextRevision`, `scaleBarStep`, `suggestCodes`, `composeBorderou` in `sheets.ts`, `cloudPath` in `markup.tsx`. |

Rule of thumb for whoever ports: open the BIMvoice file to read the behaviour and its numbers, close it, write the C#
against Lapin's own types. Never paste.

## Summary

Of 35 capabilities, Lapin **has** 22, **partly** 8, and **misses** 5 (#15, #23, #26, #27, #30). The plan/section/elevation generation, every
annotation kind (manual and automatic dimensions, texts, levels, grids, room tags), DXF, title blocks, 3D on sheets and
revisions are already there, mostly further than BIMvoice went. What BIMvoice has and Lapin does not is concentrated in
three places: reading two things from foreign IFC files (grids, true north), the PDF as an archival, layered document,
and batch production of sheets.

## Gaps worth doing, in order

1. **IfcGrid → native grid axes on IFC import** (#15, M). Every structural/architectural IFC from Revit, ArchiCAD or
   Tekla carries a grid; today it disappears on import. Reference: `readGrids` in BIMvoice `ifcdocs.ts` (the user's own).
   Engine work, Opus; tests first with a small grid file and the fidelity gate.
2. **PDF layers (OCG)** (#26, M). The pens already know their layer for DXF; the PDF gains a switchable layer tree
   (model by role, annotations by category, sheet). Written from ISO 32000.
3. **PDF archival metadata** (#27, S–M). PDF 1.7, `/ID`, XMP with sheet number, revision and issue, sRGB output intent;
   ties the PDF to the issue manifest. Written from ISO 32000/XMP. Natural to do together with 2.
4. **True north from IFC** (#23, S). Read the Model context's `TrueNorth` when there is no map conversion.
5. **Sheets for storeys / for selected views** (#30, M), with the **row layout of several views** (#20) as its placing
   rule and as an **Arrange views** action.
6. Smaller follow-ups: scale bar and north arrow under each viewport automatically (#22), "fits at 1:… / on A…" in
   placing and checks (#19), the register in front of the combined issue PDF and a live sheet list (#31), remarks drawn on
   sheets in Lapin, gated at issue (#33, with Atrium).

Nothing from the ifc-lite packages or from the vendored IfcSheet files is copied; before reusing any line of the CDE's
own code, confirm with the user that Petru Conduraru has no share in it (the BIMvoice README leaves the licence "to be
confirmed with Petru").
