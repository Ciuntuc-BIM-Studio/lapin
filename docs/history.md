# What was built

The project's history, moved out of `CLAUDE.md` on 09.11.2026 so it is no longer loaded in every session. New finished work goes at the end, one paragraph each; the decisions are in `docs/decisions-pending.md`.

M1–M7 and the roofs are done as a PoC (2026-10-24): layered walls with joins, zones and lintels; floors; structure; roofs with walls under them; doors and windows with their configurator; materials and drafting standards; the 2D drawings (plans, sections, elevations, annotations); sheets with PDF and DXF; joinery and lintel schedules; phases; old projects (format 2) open; the macOS build. A second round added CAD drafting (command line, snaps, ortho, tracking, layers), the `studio` module (solids from sketches, live booleans), the `civil` module (terrain from survey points and LandXML, platforms), steel profiles, slab and roof openings, VV/graphics sets, a Romanian UI and an MCP bridge (`docs/mcp.md`). The old Lapin's issue list is checked in `docs/issues-old-lapin.md`. A third round (25.10.2026) added the IFC export, and the UX items #115–118: 2D zoom commands, panes (split) and detached view windows, Lapin's own tool icons (`ui/src/icons`), the key plan over the views. Then `docs/plan-direct-editing.md` (#119): grips on axes, outlines and sketches, live length and angle input, the spreadsheet-style properties panel with user parameters, CAD names and roles, closed/morphing/two-rail sweeps and lofts, seven new dimension kinds, the cut order in Manage, Studio classes and types, walls attached to roofs. Then (#121): curved walls and beams (an arc axis, joined by its tangent), grips in 3D, the cut order by material, type parameters inherited by elements, curtain walls with their configurator, flip arrows in plan, move to storey. Then (25.10.2026) the visual seams: where one material goes on in the same plane from one element into another (a facade over the storey above), no line is drawn between them, in 3D, elevations and sections (`Seams`, `SeamTests`); the elements stay apart. Then `docs/plan-views-and-joinery.md` (#125–127): the browser's sets and duplicating views, sheets, levels and 3D views; the joinery configurator's drawings from the symbol engine, used by plans and elevations; reveals, sills, surrounds and thresholds as parts of doors and windows.

Then the engine in the browser (#124, `docs/plan-browser-engine.md`, stages 1–4 done on 25.10.2026): the same engine AOT-compiled in a Web Worker, 6.8 MB, 2.4× native; the desktop unchanged. Live at https://lapin.ciuntucbimstudio.ro/web/ (`deploy/web/deploy.sh`).

Then (#129): foreign IFC recognised into native elements on import (`docs/spec-ifc.md`, Recunoașterea): `IIfcRecognizer` in the platform, bodies read as prisms, walls with axes, layers, openings, doors and windows, floors, columns, beams, pad footings; the rest as references drawn with real faces.

Then (26.10.2026, #130): native DXF import (`docs/dxf-import.md`): layers, shapes, hatches with the file's patterns, texts, linear dimensions, blocks exploded; into sections and elevations on the view's plane, mirrored when the view looks towards −X or −Y; `JOIN` welds lines into polylines.

Then (#131) the testers' reports of 21–23.10 resolved: the material picker, separation pens, line caps, textures per face, project units (metric and imperial), hatch origins; the reports script is `deploy/feedback/reports.sh`.

Then (#132) links: IFC and DXF files linked read-only (`docs/links.md`), Manage → Links (show, halftone, reload, convert, open separately, unlink), View → Fog.

Then (#134) versions in the `.lapin` file (`docs/versions.md`): each a manifest in `versions/index.json`, the parts the live project no longer has kept once under `versions/blobs/`; Manage → Versions (save, rename, update to current with revisions, restore as one undo step, compare element by element, export, open separately, delete).

Then (#136) a new project starts with Foundations, Ground floor and First floor; a plan draws only its own storey's elements unless its view says otherwise (View → Storeys shown, or the plan view's properties: some or all storeys, halftone), in the engine's drawing so sheets print it.

Then (#137) the visual joins are complete by default (a cut side another area's corner stands on is split there, so a core running through a butt corner no longer draws the boundary), and view styles (`docs/view-styles.md`): Architectural, Structural (cores only), MEP and the project's own, each with its layers (all, without finishes, core), joins and overhead; a view takes its discipline's style and may override any field (View → View settings, Manage → View styles); finishes by the material's category.

Then (#138) a view's or sheet's discipline is chosen in its properties and the browser files it under that discipline's set; the properties panel shows the view in front when nothing is selected. Then (#139) a drawing's settings live in the properties panel while it is selected in the browser: discipline, style, view range, reference level (kept on the plan view), graphics, storeys shown.

Then (#141) the 3D mesh exports (`docs/plan-mesh-export.md`): glTF/GLB, OpenUSD (USDA, USDZ) and COLLADA 1.4.1 (#142) written by `engine/src/Platform/Lapin.Mesh` after their public specifications, no dependencies; File → Export 3D…; textures and OBJ next, imports later if needed. Then (#147) doors and windows say how they open in IFC by IFC's own rule (+Y the way the panels open, left and right seen looking that way): OperationType/PartitioningType, panel and lining properties, an oriented placement and a mirrored type for elements flipped on one axis; the import reads them back (`docs/spec-ifc.md`, Deschiderea ușilor și ferestrelor). **Structural analysis, stage S1 (12.11.2026, decision 503; docs/plan-fem.md §9).** Linear static analysis of bars, Lapin's own C# solver (`Lapin.Analysis/Solver`). It uses 3D bar elements with 12 degrees of freedom, Timoshenko by default (shear areas from the sections' geometry, after EN 1993-1-1 6.2.6), rigid arms for eccentric ends and for unsymmetric sections' centroids, and releases by static condensation. Releases are the element's own `analysisReleases` (`analysis.setReleases`) or the defaults of `FrameReleases`: a connection's cleat, gusset or fly brace pins; timber roof members are pinned about the strong axis where they bear; the rest is fixed. The model is assembled with Reverse Cuthill-McKee ordering and factored once by a skyline LDLᵀ for every case. A turning that moves no node is held by a spring, and a real mechanism is reported with its node, degree of freedom and the parts that move. Reactions are R = K·U − F, and the balance is checked on every case. Load-bearing walls are line supports until S2 (shells). Loads come from S0. Slabs carry theirs to beams and walls by the 45° rule, and framed roofs to their rafters by tributary width on each real roof plane (snow per horizontal projection). Point and line loads on a slab with no bar under them go to its corners by statically consistent weights. Combinations are built by superposition, with ULS and SLS envelopes. Results are derived and cached in memory by revision: `analysis.run`, `analysis.results` (displacements, reactions, N/Vy/Vz/T/My/Mz at 11 stations with exact extremes, deflection) and `analysis.diagram` (world polylines). The structural IFC view writes releases as `AppliedCondition` and eccentric ends as `IfcRelConnectsWithEccentricity`. In the interface, Run analysis opens the results dialog (balance per case, refused bars, the mechanism with the elements to select, the maxima). A 3D card draws the diagrams, the deformed shape and the reactions, its labels kept apart. A bar's Analysis section takes its releases and shows its extremes. A new `overlays3d` hook on UI modules lets a module draw in 3D. The solver was checked against closed forms (cantilever, simply supported and continuous beams, portal, torsion, releases, offsets, shear) and, at development only, against PyNite (1e-15). Timings: 26,460 DOFs in 14 s. Tests: `FrameSolverTests`, `LoadMappingTests`, `AnalysisRunTests`, `FramedRoofLoadTests`, `StructuralIfcTests`. **Structural analysis, stage S2a: shells and the sparse solver (12.11.2026, decision 513; docs/plan-fem.md §10).** The library behind S2, Lapin's own MIT code written from the published literature, with no code or dependency from any FE or sparse library. It goes in `Lapin.Analysis/Solver`, and its wiring into `analysis.run` is S2b.
- **Shell element** (`ShellElement`): a flat element of 4 or 3 nodes with 6 degrees of freedom a node. Bending is MITC4 on quadrilaterals (Dvorkin and Bathe 1984–85) and MITC3 on triangles (Lee and Bathe 2004), so thick and thin plates take the same element without shear locking. The membrane uses Allman's interpolation with a true drilling rotation tied by the Hughes–Brezzi penalty (γ = G, after Ibrahimbegović, Taylor and Wilson 1990), so no fictitious θz spring is needed where shells meet bars or each other. Loads are consistent nodal shares. Stress resultants (N, M, Q) come at the centre and the corners.
- **Results at nodes** (`ShellSmoothing`): the corner mean, and Zienkiewicz–Zhu patch recovery fitted on the element centres (Barlow points). At a clamped edge the recovery is 0.9 % from theory where the corner mean is 12 % off.
- **Solver**: `FrameSolver` takes shells next to bars (`FrameProblem.Shells`, `CaseLoads.Surface`, `CaseResult.Shells`, `ShellResult.Combine`), on shared nodes, with reactions, balance, mechanisms and springs as before. It gained iterative refinement, which keeps the balance at 1e-9 on badly conditioned models whatever the elimination order.
- **Mesher** (`ShellMesher`): the convex plane pieces of `ShellPieces` become quadrilaterals. Edges are cut first at hard points (bar nodes, other pieces' corners), then into equal parts no longer than the target size, keyed by their end nodes, so neighbouring pieces and bars share nodes (`ShellMesh.NodesAlong`). A four-sided piece with matching opposite sides is meshed by transfinite interpolation, all quadrilaterals. Any other piece gets a Delaunay triangulation (Lawson flips), safe Laplacian smoothing and best-first pairing into quadrilaterals, which puts 86–91 % of the area in quadrilaterals.
- **Sparse factorization** (`SparseCholesky`): supernodal left-looking Cholesky (Ng–Peyton, Davis). Equations are grouped by node and ordered by approximate minimum degree (Amestoy–Davis–Duff) or by nested dissection (George), whichever predicts less work. Supernodes come from the postordered elimination tree. Large blocks run in parallel on desktop and serially in the browser. It replaces the S1 skyline as `FrameSolver`'s default (`FactorKind.Skyline` stays to compare), with the same results to 1e-9. Frames of 23,814 / 80,724 DOFs take 0.73 s / 4.0 s, against 4.3 s / 76 s for the skyline, and the factor needs 403 MB against 1.1 GB. A clamped plate of 133k / 192k DOFs takes 3.6 s end to end.
- **Tests against closed forms**: simply supported and clamped plates (Timoshenko and Woinowsky-Krieger) converge to 0.1 % at 32 × 32. Thin plates do not lock up to a/t = 10,000. A cantilever wall in its plane agrees with Timoshenko's beam to 0.4 % at 8 × 32, and Scordelis–Lo's roof gives 0.3014 against 0.3024. MacNeal–Harder patch tests pass exactly, every element has six rigid-body modes and no spurious one, and a slab on beams on rigid arms balances and shows composite action. The solver matches dense factorization and the skyline.
- **Development cross-check**: `scripts/fem-check/pynite_plate.py` compares against PyNite's DKMQ quadrilaterals; on these plates Lapin is closer to theory.
- **Tests and the S2b spec**: `ShellElementTests`, `ShellMesherTests`, `SparseCholeskyTests` (big frames and plates timed with `LAPIN_FEM_BENCH=1`). §10.10 specifies S2b: meshing slabs and walls in the analysis, bars cut on the mesh nodes with offset_z as rigid arms, loads on elements with the 45° rule retired, `analysis.contours`, contours in 3D and plan through the visibility resolver, and the guide.
