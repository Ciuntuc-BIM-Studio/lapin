# What was built

The project's history, moved out of `CLAUDE.md` on 09.11.2026 so it is no longer loaded in every session. New finished work goes at the end, one paragraph each; the decisions are in `docs/decisions-pending.md`.

M1–M7 and the roofs are done as a PoC (2026-10-24): layered walls with joins, zones and lintels; floors; structure; roofs with walls under them; doors and windows with their configurator; materials and drafting standards; the 2D drawings (plans, sections, elevations, annotations); sheets with PDF and DXF; joinery and lintel schedules; phases; old projects (format 2) open; the macOS build. A second round added CAD drafting (command line, snaps, ortho, tracking, layers), the `studio` module (solids from sketches, live booleans), the `civil` module (terrain from survey points and LandXML, platforms), steel profiles, slab and roof openings, VV/graphics sets, a Romanian UI and an MCP bridge (`docs/mcp.md`). The old Lapin's issue list is checked in `docs/issues-old-lapin.md`. A third round (25.10.2026) added the IFC export, and the UX items #115–118: 2D zoom commands, panes (split) and detached view windows, Lapin's own tool icons (`ui/src/icons`), the key plan over the views. Then `docs/plan-direct-editing.md` (#119): grips on axes, outlines and sketches, live length and angle input, the spreadsheet-style properties panel with user parameters, CAD names and roles, closed/morphing/two-rail sweeps and lofts, seven new dimension kinds, the cut order in Manage, Studio classes and types, walls attached to roofs. Then (#121): curved walls and beams (an arc axis, joined by its tangent), grips in 3D, the cut order by material, type parameters inherited by elements, curtain walls with their configurator, flip arrows in plan, move to storey. Then (25.10.2026) the visual seams: where one material goes on in the same plane from one element into another (a facade over the storey above), no line is drawn between them, in 3D, elevations and sections (`Seams`, `SeamTests`); the elements stay apart. Then `docs/plan-views-and-joinery.md` (#125–127): the browser's sets and duplicating views, sheets, levels and 3D views; the joinery configurator's drawings from the symbol engine, used by plans and elevations; reveals, sills, surrounds and thresholds as parts of doors and windows.

Then the engine in the browser (#124, `docs/plan-browser-engine.md`, stages 1–4 done on 25.10.2026): the same engine AOT-compiled in a Web Worker, 6.8 MB, 2.4× native; the desktop unchanged. Live at https://lapin.ciuntucbimstudio.ro/web/ (`deploy/web/deploy.sh`).

Then (#129): foreign IFC recognised into native elements on import (`docs/spec-ifc.md`, Recunoașterea): `IIfcRecognizer` in the platform, bodies read as prisms, walls with axes, layers, openings, doors and windows, floors, columns, beams, pad footings; the rest as references drawn with real faces.

Then (26.10.2026, #130): native DXF import (`docs/dxf-import.md`): layers, shapes, hatches with the file's patterns, texts, linear dimensions, blocks exploded; into sections and elevations on the view's plane, mirrored when the view looks towards −X or −Y; `JOIN` welds lines into polylines.

Then (#131) the testers' reports of 21–23.10 resolved: the material picker, separation pens, line caps, textures per face, project units (metric and imperial), hatch origins; the reports script is `deploy/feedback/reports.sh`.

Then (#132) links: IFC and DXF files linked read-only (`docs/links.md`), Manage → Links (show, halftone, reload, convert, open separately, unlink), View → Fog.

Then (#134) versions in the `.lapin` file (`docs/versions.md`): each a manifest in `versions/index.json`, the parts the live project no longer has kept once under `versions/blobs/`; Manage → Versions (save, rename, update to current with revisions, restore as one undo step, compare element by element, export, open separately, delete).

Then (#136) a new project starts with Foundations, Ground floor and First floor; a plan draws only its own storey's elements unless its view says otherwise (View → Storeys shown, or the plan view's properties: some or all storeys, halftone), in the engine's drawing so sheets print it.

Then (#137) the visual joins are complete by default (a cut side another area's corner stands on is split there, so a core running through a butt corner no longer draws the boundary), and view styles (`docs/view-styles.md`): Architectural, Structural (cores only), MEP and the project's own, each with its layers (all, without finishes, core), joins and overhead; a view takes its discipline's style and may override any field (View → View settings, Manage → View styles); finishes by the material's category.

Then (#138) a view's or sheet's discipline is chosen in its properties and the browser files it under that discipline's set; the properties panel shows the view in front when nothing is selected. Then (#139) a drawing's settings live in the properties panel while it is selected in the browser: discipline, style, view range, reference level (kept on the plan view), graphics, storeys shown.

Then (#141) the 3D mesh exports (`docs/plan-mesh-export.md`): glTF/GLB, OpenUSD (USDA, USDZ) and COLLADA 1.4.1 (#142) written by `engine/src/Platform/Lapin.Mesh` after their public specifications, no dependencies; File → Export 3D…; textures and OBJ next, imports later if needed. Then (#147) doors and windows say how they open in IFC by IFC's own rule (+Y the way the panels open, left and right seen looking that way): OperationType/PartitioningType, panel and lining properties, an oriented placement and a mirrored type for elements flipped on one axis; the import reads them back (`docs/spec-ifc.md`, Deschiderea ușilor și ferestrelor). **11.11.2026 — SDNF: curved members, holes and the bolts' holes (decision 480).** The SDNF exchange of decision 474 now carries packets 60 and 22, after their record tables on AVEVA's SDNF page (pictures beside it) and the packet lists of Tekla, SDS2 and ProStructures (docs/sdnf.md). **Curved members (packet 60):** eleven records, a linear member's ten with the arc between its second and third (centre, start angle, sweep, the plane's normal). Lapin's curved members are the structure's curved beams (an arc in plan, `PathCurve`; steel members stay straight), so the export writes each curved beam as a straight one is written (its clear span along the arc at its top, cardinal point 8, the columns' centres as the offsets to its nodes) with the normal about which the sweep turns counter-clockwise and the start angle from the plane's x (Lapin's reading: the descriptions say neither); the import makes a level curved member with its section upright a curved beam (the cardinal point's line moved to the top centre, across the arc a smaller or larger radius; the rise from the centre, the ends and the turn), and leaves out and says one arching in another plane. **Holes (packet 22):** number and parent plate, periphery, depth, vertices per face, the two loops, two records more. Imported, a through hole is cut in its plate's body (`Prism` with holes, laid onto the face along the thickness, kept when inside), the plate keeping its SDNF definition and holes (`sdnf.def`, `sdnf.holes`) so the export writes it back under its own number (imported plates were not exported before); a hole whose parent is a member (as Lapin writes a member's holes) is kept on the member in its frame (`MemberHoles`, attribute `holes`: section x, y and the station from the member's own start, so it moves with it), taken off the body by manifold in the steel module's geometry and written to IFC as an opening of its swept body. Recesses, holes off their plate and holes naming nothing are said. A file read again puts its holes in place of an element's: never doubled, and gone when the file no longer has them. **Bolts:** no SDNF packet carries them, so the import says the holes came without them; the export writes the holes the connections' bolts and anchors make in their plates (each fastener line crossing both faces within its grip, inside the outline, round at `NodeSpec.Hole`: 2 mm over the bolt, 3 mm past M24), from the lines `SteelNodes.Build` now records (`BoltLines`). **Arrays that keep their arrangement, and along a path (decision 481, 11.11.2026).** Modify → Array no longer leaves just N copies: `element.array` makes a `LapinArray` beside them (`Lapin.Platform/Arrays.cs`), a Lapin resource the IFC export never writes, holding the rule and its items (the original first, then each copy with the ids it is and the pose the rule gave it). Besides the row (a step, or `fit` an extent shared out) and the polar array, there is now **along a path**: `{kind: "path", along | points, count | spacing, start, end, offset, orient: "tangent" | "fixed", flip, base}`. What an array can follow is asked of the modules (`IArrayPaths`): Drafting's lines, polylines, arcs and circles in a plan (arcs exactly), Civil's roads, paths, ditches and retaining walls along their alignment (`Chain`, curves and clothoids exactly) and site feature lines; without one, a path element's axis (`PathCurve`, arched walls exactly) or the line a section would follow. `array.update` places the items again by the difference between where the rule put each and where it puts it now, so the copies keep their GlobalIds, one moved by hand keeps its offset, one deleted stays a gap, new ones are copied from the original and the surplus deleted, in one undo step; a path element edited by any command moves the copies along it in that command's step (`IDrivenElements.After`), and a path deleted leaves its last line. Each copy is made, and each move done, through `ElementTransform.Run`, so a module driving its elements (`IDrivenElements.Before`, `Copy`) makes its copies its own way. `array.explode` leaves the copies plain; `array.of` and `array.preview` (the rule's places, for the tool's ghost) are queries. The interface: *Along a path* in the Array dialog, then a click on the path with the engine's preview and the base point; an Array section in the properties of any copy (count, step, angle, spacing, ends, offset, orientation; Select the array, Explode). **Content of an absent module (decision 484, 11.11.2026).** A project holding what a module this edition lacks wrote opens, is edited, saved and exported as any, that content kept as it came. **Cut parts and needle triangles (decision 485, 11.11.2026).** Cut priorities now take out of each part of an element only the cutters whose box meets that part's own, no longer every cutter that reaches the element's whole box. A roof's downpipes take its box down to the ground, so a floor anywhere under the roof cut its covering, which it never touches, and the covering came back non-manifold. A roof over floors builds about a third faster, since fewer pairs are cut. A triangle mesh read back from the boolean library no longer loses its needle triangles (three corners on one line): such a triangle joined no face and its three edges were left open; its middle corner is now put on the triangle across its long edge, which is split in two, so the solid stays closed. Seen on a wall cut for a window with an outside sill and a reveal in its own material, with or without finish layers. Tests: `CutPartsTests`, `RevealSillShellTests`, `SolidFromMeshTests`. Left: the lintel is not cut by the reveal's head, which reaches 20 mm above the opening.
